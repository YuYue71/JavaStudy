## java.util.concurrent：執行緒池與結果

```java
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
```

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
Future<Integer> future = pool.submit(() -> 2 + 3);
try {
    int result = future.get(3, TimeUnit.SECONDS); // 最多等待 3 秒
    System.out.println(result);
} catch (TimeoutException e) {
    future.cancel(true); // 發出中斷請求，不保證任務一定停止
} catch (InterruptedException e) {
    future.cancel(true);
    Thread.currentThread().interrupt();
} catch (ExecutionException e) {
    System.err.println(e.getCause()); // 背景任務的例外
} finally {
    pool.shutdown();
    try {
        if (!pool.awaitTermination(5, TimeUnit.SECONDS)) pool.shutdownNow();
    } catch (InterruptedException e) {
        pool.shutdownNow();
        Thread.currentThread().interrupt();
    }
}
```

| 方法／型別 | 使用方式 |
|---|---|
| Runnable | `() -> System.out.println("工作")`，沒有回傳值 |
| Callable<T> | `() -> 42`，可回傳值與拋 checked exception |
| execute | 提交 Runnable，沒有 Future |
| submit | 提交任務，取得 Future |
| Future.get | 阻塞等待；任務失敗包成 ExecutionException |
| shutdown | 不再接新工作，已提交工作繼續 |
| shutdownNow | 嘗試中斷執行中任務，回傳未開始工作，不保證立即停止 |
| awaitTermination | 關閉後等待工作結束，回傳是否已全部結束 |

Java 17 的 ExecutorService 不支援 try-with-resources；虛擬執行緒也不是 Java 17 的正式功能。newFixedThreadPool 使用的待處理佇列可持續增長，大量任務需考慮有界佇列與拒絕策略。

## CompletableFuture：串接非同步步驟

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
try {
    CompletableFuture<String> task = CompletableFuture
            .supplyAsync(() -> 21, pool)
            .thenApply(n -> n * 2)
            .thenApply(n -> "答案：" + n)
            .orTimeout(3, TimeUnit.SECONDS)
            .exceptionally(error -> "處理失敗：" + error.getClass().getSimpleName());
    System.out.println(task.join());
} finally {
    pool.shutdown();
}
```

| 操作 | 用途 |
|---|---|
| thenApply | 轉換上一階段值 |
| thenAccept | 消費值，不回傳資料 |
| thenCompose | 串接另一個回傳 CompletableFuture 的非同步操作 |
| thenCombine | 合併兩個獨立非同步結果 |
| exceptionally | 失敗時回傳替代值 |
| whenComplete | 觀察成功／失敗，常用於記錄 |
| join | 等待結果，失敗通常拋 CompletionException |

非 Async 的接續步驟不保證使用新執行緒。orTimeout 讓 Future 逾時失敗，不保證底層工作被取消；不要以為逾時就沒有背景工作。

## 排程、共享狀態與並行容器

```java
ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
scheduler.schedule(() -> System.out.println("延遲工作"), 1, TimeUnit.SECONDS);
scheduler.shutdown(); // 已排程的一次性工作預設仍會執行

AtomicInteger counter = new AtomicInteger();
int current = counter.incrementAndGet();
ConcurrentMap<String, Integer> counts = new ConcurrentHashMap<>();
counts.merge("Java", 1, Integer::sum);
```

| 工具 | 使用時機與限制 |
|---|---|
| synchronized | `synchronized (lock) { ... }` 保護複合操作，共用同一把鎖才有效 |
| volatile | 欄位更新的可見性；`count++` 仍不是原子操作 |
| AtomicInteger | 單一數值原子更新；多欄位一致性仍需另處理 |
| ConcurrentHashMap | 並行鍵值查詢／更新，不接受 null；複合更新用 compute/merge |
| BlockingQueue | 生產者消費者；put/take 可能阻塞並受中斷 |
| scheduleAtFixedRate | 依固定週期排程；例外可能使後續執行停止 |
| scheduleWithFixedDelay | 上次結束後等待固定延遲再執行 |

避免忙等與把鎖持有到網路／檔案操作結束。捕捉 InterruptedException 後通常恢復中斷旗標，或向上傳遞給能處理的呼叫端。

## java.util.logging：內建日誌

```java
import java.util.logging.Logger;
import java.util.logging.Level;
```

```java
Logger logger = Logger.getLogger("app.reference");
logger.info("應用啟動");
logger.fine(() -> "僅在細節層級啟用時建立這段文字");
try {
    Integer.parseInt("abc");
} catch (NumberFormatException e) {
    logger.log(Level.WARNING, "輸入解析失敗", e);
}
```

| 層級 | 用途 |
|---|---|
| SEVERE | 嚴重錯誤 |
| WARNING | 可恢復問題、需要關注 |
| INFO | 一般重要事件 |
| CONFIG | 設定資訊 |
| FINE / FINER / FINEST | 逐步增加細節 |

日誌要通過 Logger 與 Handler 的層級過濾，單獨提高 Logger 詳細度可能仍看不到 FINE。不要記錄密碼、token 或完整敏感資料；例外用 log(level, message, exception) 保留堆疊。
